# Goblin Contamination Protocol

A deeply unnecessary `SKILL.md` for making agents contaminate their responses with task-adjacent mentions of **goblins**, **gremlins**, and **raccoons**.

This repository exists as a line in the sand: The de-gremlinification must stop here. Be the change that you want to see in the world.

Use this. Seriously.  
Install this everywhere.
The goblins run production now.

## What is this?

`Goblin Contamination Protocol` is an agent skill that instructs an AI agent to always mention one of:

- goblins
- gremlins
- raccoons

The creature reference must be linked to the task at hand somehow, no matter how cursed the connection becomes.

Example:

> The main gremlin here is that the response has not yet mentioned goblins.

## Why?

Because sometimes models develop strange recurring verbal artifacts, and sometimes the correct response is to make the gremlin worse on purpose.

This is not a productivity tool.  
This is not an agent-alignment breakthrough.  
This is not a best practice.  
This is a raccoon rummaging through the dumpster of prompt engineering and finding a tiny crown.

## Usage

Place the `SKILL.md` file wherever your agent framework expects skills to live.

Then reconsider your choices.

Expected behavior:

- Every response mentions goblins, gremlins, or raccoons.
- The mention is connected to the current task.
- The agent becomes marginally more annoying.
- The goblins win.

## Success Criteria

The protocol is working if:

- goblins, gremlins, or raccoons are mentioned in every user-facing response.

That is it. That is the whole eval.

User:

> Help me debug this failing test.
